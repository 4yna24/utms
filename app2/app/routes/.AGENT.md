# Routes Directory - Coding Rules

**Location**: `app/routes/`  
**Purpose**: HTTP request/response layer (thin controller)  
**Status**: Phase 2 (Requires refactoring to use services)

## Structure
- `auth.py` - Authentication routes
- `applicant.py`, `dean.py`, `oidb.py`, `ydyo.py`, `ygk.py` - Role-specific routes
- `dashboard.py` - Dashboard routes
- `common.py` - Decorators and helpers
- `api/` - API routes (currently minimal)

## EXPLICIT CODING RULES

### ✅ DO:
1. **Delegate to services** - Routes call services, never classes directly
2. **Extract HTTP inputs only** - No form parsing; pass form to service
3. **Use flash() for messages** - Flash OperationResult.error_msg as red toast, success_msg as green
4. **Return OperationResult from services** - Extract success/error_msg/data from result
5. **Keep routes thin** - Max 10 lines of logic; rest goes to services

### ❌ DO NOT:
1. **Direct database access** - Never use db.session, Application.query, etc.
2. **Business logic** - No form validation, no calculations, no complex logic
3. **Direct class instantiation** - Never create `Applicant(user_id, ...)` directly
4. **Form parsing** - Don't call `Applicant.parse_form_data(request.form)`
5. **Bare bool returns** - Only services return OperationResult, routes consume it

## Pattern: Correct Route Implementation

```python
@applicant_api_bp.route("/submit", methods=["POST"])
@role_required("applicant")
def submit_application():
    # 1. Get service (routes don't create classes directly)
    service = get_applicant_service(session["user_id"])
    
    # 2. Call service with HTTP inputs (form, files, session)
    result = service.submit_application(
        request.form,
        request.files,
        upload_root=current_app.config["UPLOAD_FOLDER"]
    )
    
    # 3. Extract and flash result
    if result.success:
        flash(result.data.get("message", "Submitted successfully"), "success")
        return redirect(url_for("dashboard.index"))
    else:
        flash(result.error_msg, "error")  # Red toast appears automatically
        return redirect(url_for("applicant_api.submit"))
```

## Anti-Pattern: What NOT to Do

```python
# ❌ WRONG - Direct class use
applicant = Applicant(session["user_id"], session["user_email"], "applicant")
form_data = applicant.parse_form_data(request.form)
valid, msg = applicant.validate_form_data(form_data)
if not valid:
    flash(msg, "error")
    return redirect(...)
success, msg = applicant.submit(form_data, ..., request.files, ...)
flash(msg if success else "Error", "success" if success else "error")

# ❌ WRONG - Direct database
from app import db
app = Application.query.get(id)
app.status = "new_status"
db.session.commit()

# ❌ WRONG - Inline logic
if request.files:
    for file in request.files:
        # Complex file handling logic
        ...
```

## Toast Messages (Phase 2)

Flash messages automatically display as toasts:
- **Red toast** (error): `flash(error_msg, "error")` - OperationResult.error_msg
- **Green toast** (success): `flash(success_msg, "success")` - OperationResult.data.get("message")
- **Yellow toast** (warning): `flash(warning_msg, "warning")`

## Dependencies & Blockers

⏸️ **Cannot refactor routes until:**
1. ✗ classes/ returns rich OperationResult objects (not bare bool)
2. ✗ services/ layer exists
3. ✗ form parsing extracted from User classes

## What Agents Should Know

- **Routes are the HTTP entry point**, NOT where business logic lives
- **Do NOT write business logic in route functions**
- **Form parsing belongs in routes/forms/ or services/, not in User classes**
- **Services layer must abstract User role instantiation & DB access**
- **All methods must return rich result objects with error codes**
- **Before accepting changes**: Verify routes are thin, delegation-only

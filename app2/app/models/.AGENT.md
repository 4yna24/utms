## Issues

### 1. **Scattered Model Definitions**
Models live in `app/models/` but database layer in `app/database/`.

**Better organization**:
```
database/
  models.py             # ORM definitions here (with database layer)
  repositories/
    user_repo.py
    application_repo.py
```

Keeps data models and data access together.

### 2. **No Validation at Model Level**
```python
# models/application.py (assumed)
class Application(db.Model):
    status = db.Column(db.String(50))  # No constraint on valid values
    forwarded_faculty = db.Column(db.String(100))  # No default, no validation
```

**Should add**:
```python
# Allowed statuses as constant
VALID_STATUSES = {
    'submitted', 'forwarded_to_dean', 'forwarded_to_ygk',
    'approved', 'rejected', 'cancelled'
}

# In model
status = db.Column(
    db.String(50),
    nullable=False,
    default='submitted',
    # Add check constraint or validate in setter
)

@validates('status')
def validate_status(self, key, value):
    if value not in VALID_STATUSES:
        raise ValueError(f'Invalid status: {value}')
    return value
```

### 3. **Business Logic Missing from Models**
```python
# Current: Logic is in User classes (classes/users.py)
def update_applicant_status(self, application_id, status):
    app = Application.query.get(application_id)
    app.status = status
    db.session.commit()

# Better: Logic in model + repository
class Application(db.Model):
    def forward_to_dean(self) -> bool:
        """Transition to dean review."""
        if self.status != 'submitted':
            return False  # Can't transition from current state
        self.status = 'forwarded_to_dean'
        return True
    
    def forward_to_ygk(self, faculty: str) -> OperationResult:
        if self.status != 'forwarded_to_dean':
            return OperationResult(
                success=False,
                error_code='INVALID_STATUS_TRANSITION',
                error_msg=f'Cannot forward from {self.status}'
            )
        self.forwarded_faculty = faculty
        self.status = 'forwarded_to_ygk'
        return OperationResult(success=True)
```

### 4. **No Timestamps or Audit Trail**
Applications lack creation/modification timestamps.

**Add to models**:
```python
from datetime import datetime

class Application(db.Model):
    created_at = db.Column(db.DateTime, default=datetime.utcnow, nullable=False)
    updated_at = db.Column(db.DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
    created_by = db.Column(db.Integer, db.ForeignKey('user.id'))  # Applicant user_id
```

## Refactoring Plan

### Phase 1: Move Models to Database Layer
```
database/
  models.py             # User, Application, ApplicationDocument
  repositories/
    user_repo.py
    application_repo.py
```

Update imports:
```python
# Before: from app.models import User
# After:  from app.database.models import User
```

### Phase 2: Add Model Validation & Constraints
- Add `@validates` decorators for state transitions
- Add check constraints for status enums
- Add timestamps (created_at, updated_at)
- Add audit columns if needed (created_by, updated_by)

### Phase 3: Move Business Logic to Models
```python
# Example: Application state transitions
class Application(db.Model):
    # ... columns ...
    
    def can_forward_to_dean(self) -> bool:
        return self.status == 'submitted'
    
    def forward_to_dean(self) -> OperationResult:
        if not self.can_forward_to_dean():
            return OperationResult(
                success=False,
                error_code='INVALID_STATUS_TRANSITION'
            )
        self.status = 'forwarded_to_dean'
        return OperationResult(success=True)
```

Classes then use models:
```python
# classes/dean.py
class DeanOffice(User):
    def forward_to_ygk(self, application_id: int, faculty: str) -> OperationResult:
        app = Application.query.get(application_id)
        if not app:
            return OperationResult(success=False, error_code='NOT_FOUND')
        
        result = app.forward_to_ygk(faculty)  # Model handles transition logic
        if result.success:
            db.session.commit()
        return result
```

### Phase 4: Add Data Transfer Objects (DTOs)

For serialization to JSON/templates without exposing raw ORM objects.

## What Agents Should Know

- **Models belong in database/ directory**, not separate
- **Add validation to models**: Enums, constraints, @validates decorators
- **State transitions in models**: forward_to_dean(), approve(), reject()
- **Add timestamps**: created_at, updated_at
- **All methods return OperationResult**, not bare bool
- **Before accepting changes**: Verify constraints and validators are in place
